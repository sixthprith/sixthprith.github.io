Why I built it

I live two hours from Cape Canaveral and I love rockets and military aviation. I kept missing things: a Falcon Heavy I found out about the next morning, an airshow I heard of a week late.

Launch schedules live on one site, airshow schedules on several others, and none of them answer the questions I actually have. Is it close enough to drive to? Can I see it from home? Which way do I face? Will there be clouds in the way?

So I built one page that answers all four.

What it does

  • Shows every upcoming event on one map, with a pin for each launch pad and airshow venue and a countdown that ticks in real time.
  • Tells you where to look. Each event gets a compass bearing and distance from home, so a launch you can't drive to can still be watched from the backyard.
  • Filters by how far you'll drive. A radius knob runs from 25 to 250 nautical miles, and time filters cover the next week, month or season.
  • Reads the sky for you. Switch on sky conditions and it pulls live airport weather for eleven Florida stations, then translates the cloud layers into what they mean for someone watching from the ground, including fog risk.
  • Pulls real launch details: the launch window, the orbit, the chance of a go, and a link to the webcast.
  • Reminds you. A calendar feed you subscribe to once puts every event on your phone, with new launches appearing by themselves.

How it works

There is no server and no database. Everything runs in the visitor's browser or on GitHub's free automation, which is why it costs nothing to keep alive.

Data comes in

Launches come live from the Launch Library 2 API. Airshows come from a small file I curate by hand. Weather comes from the National Weather Service.

The browser does the math

The page merges the sources, drops anything in the past, and computes great-circle distance and bearing for each event before drawing it on a Leaflet map.

A robot keeps the calendar fresh

Every six hours a GitHub Action runs a Python script that rebuilds the calendar feed and commits it. Nobody has to touch it.

Three problems worth mentioning

The weather service I planned on refused to talk to a browser

My first choice for aviation weather was the Aviation Weather Center. A live test showed it doesn't allow web pages on other domains to read its data. Rather than add a server just to relay it, I switched to the National Weather Service, which does allow it. That service only returns one station per request, so the page asks for eleven at once, skips any that fail, and converts the units itself. The whole thing takes about 150 milliseconds.

Nobody publishes airshow schedules as data

There is no API for airshows, and the published schedules sometimes disagree with each other. I keep them in a hand-edited file where each entry carries a confidence flag, so a preliminary date looks different from a confirmed one. Adding a new kind of event to that file makes its filter appear on the map automatically.

A free static site can't send notifications

I wanted my phone to tell me about a launch, but GitHub Pages can only serve files. The answer was to stop thinking about notifications and publish a calendar feed instead. Your calendar app already knows how to remind you, so the app borrows that.

The design

The map is styled after a VFR sectional, the paper chart pilots fly with: muted terrain, magenta and blue airspace colors, range rings and bearing lines radiating from home. Distances are in nautical miles and bearings are true, as they would be on the real thing.

The controls are deliberately physical. Filters are lamps that light up, and the radius is a knob you turn. It's a tool for people who like aircraft, so it should feel a little like a cockpit.

What this shows about how I work

  • I start from a real question a person has and work back to the data.
  • I test assumptions against the live system before building on them.
  • When a constraint blocks the obvious route, I look for a simpler route before a bigger one.
  • I built this with AI as a pair programmer. I set the direction, made the design decisions and verified each piece in the browser.
